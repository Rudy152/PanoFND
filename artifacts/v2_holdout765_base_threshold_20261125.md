# 基础模型调门槛的基线（765 条评测集，2026-11-25）

起因：导师建议给基础模型也在调参集上调一次判假门槛，使它和 v2 单次调用的比较更公平。数据见 [holdout765_base_threshold_20261125.json](v2_results_20261122/holdout765_base_threshold_20261125.json)，代码是 `panoagent_v2/baseline_s0.py`。

## 做法

- v1 原来只输出 REAL/FAKE，没有概率，不能调门槛。所以用表 E 的 S0：v1 的完整请求不变，只改成读取 TRUE/FALSE 的概率。
- 门槛只在 943 条调参集上选，规则与 v2 单次调用的门槛相同（`scorer._best_threshold`，使 Balanced Acc. 最大）。结果是 **0.320**，2026-11-25 22:21 冻结，冻结时还记录了代码和调参结果的哈希，之后才开始调用评测集。调参集上，样本内 Balanced Acc. 从 72.1%（0.5）升到 73.0%。
- 评测集只跑一次，没有据此选择任何东西。但这又看了一次评测集，应在论文里说明。
- 费用 2.12 元。6 条被平台内容审核拒绝（1155、1163、1571、1646、1716、1721），按出错计；v1 也有 6 条出错。

## 结论

1. **基础模型调了门槛也没有变好。** 门槛 0.320 在调参集上只多 0.9 个点，到评测集反而比 0.5 低 2.6 个点。所以把 70.9% 当作基础模型的成绩并不吃亏；按导师说的公平比较，v2 比基础模型高 13.1 到 13.3 个点。
2. **调门槛的作用依赖输入，所以三步分解与顺序有关。** 下表的四个角都是评测集上的数：

   | | 不调门槛 | 调参集门槛 |
   |---|---:|---:|
   | v1 输入 | 72.8%（0.5）/ 70.9%（v1 直接回答） | 70.3% |
   | v2 输入 | 80.2%（0.5）/ 79.3%（直接回答） | 83.4% |

   - 先改输入再调门槛：输入 +8.5，门槛 +4.1。
   - 先调门槛再改输入：门槛 −0.6，输入 +13.1。
   - 调门槛只对 v2 输入有用。v2 输入直接回答时偏向判真（REAL 召回 92%，FAKE 召回 66%），把门槛降到 0.223 后，FAKE 召回升到 82%；v1 输入没有这样的偏向。论文里写"提升主要来自输入和提示词的设计，以及与之配套的门槛"比写成两步独立的贡献更准确。
3. **S0 和 v1 那次运行不完全相同。** 两者在 759 条上的标签一致率为 89.2%，S0 直接回答比 v1 高 2.1 个点 [−0.3, +4.6]（不显著）。区别在于是否读取概率，以及运行日期不同。
4. **去掉与调参集标题相同的 94 条后（671 条）**：基础模型调门槛 69.8%，v2 单次调用调门槛 82.7%，相差 +12.9 [+9.4, +16.4]，方向不变。
