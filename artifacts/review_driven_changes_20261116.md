# 根据方法评审意见的模型修改（2026-11-16）

本次只改代码，没有调用任何 API。direct 基线的提示词逐字未改，历史结果仍然可以复现。
本地测试 108/108 通过，其中新增 `tests/test_review_fixes.py`。

| 评审意见 | 修改 | 位置 |
|---|---|---|
| 1. 外部核查只核文本，却给整条新闻“背书” | 所有 Judge 共用同一条判决规则：任一模态被篡改或任一模态对有实质冲突即判 FAKE；只有所有模态都干净、所有模态对都一致才判 REAL。检索只能推翻文本，不能证明图片、音频、视频为真。删除“找到原文且槽位一致即支持 REAL”。fused-rule 也删除了“检索确认即判 REAL”的路径，并新增模态级 FAKE 规则 | `prompts.py` `DECISION_RULE`；`aggregation.py` `modality_problems` |
| 2. 视频帧不加标注 | frames 模式在提示词中加入 `VISUAL INPUT ORDER`，注明哪几张是新闻配图、哪几张是视频帧及其时间顺序；Relation、fused 明确 image 指配图、video 指视频帧。direct 不受影响 | `media.py` `visual_manifest`；`schemas.py` `agent_text` |
| 2. 只抽 4 帧 | 运行脚本默认改为 8 帧（参数 `-FrameCount` 可调） | `scripts/run_agent_search.ps1` |
| 2. Judge 看不到媒体 | 新增可选参数 `--judge-media`，开启后 Judge 也能直接查看媒体，默认关闭 | `agents/judge.py` |
| 3. 没有图像和音频篡改的检测能力 | Unimodal 和 fused 提示词要求逐项检查生成和编辑痕迹。**未实现专门的检测模型**，需要另外引入模型 | `prompts.py` |
| 4. 槽位规则贴合数据集的造假方式 | 槽位保护和数字比对改为默认关闭（`--external-slot-guard` 开启，仅作消融）；即使开启，也必须确认找到同一篇原文才触发，删除了 0.7 阈值的路径 | `pipeline.py` |
| 4. 检索没有时间限制 | 只用新闻发布日期加 1 天以内的证据（Tavily `end_date` 加本地日期过滤）；无日期的结果保留并计数；`--no-search-date-bound` 可关闭 | `retrieval.py`；`agents/context_verifier.py` |
| 4. 未排除辟谣网站 | 默认排除 snopes、politifact、factcheck.org、fullfact、AFP 事实核查等 14 个站点 | `retrieval.py` `FACT_CHECK_DOMAINS` |
| 4. 提示词中针对个别样本的补丁 | 删除 Belter/Boelter 等人名、192%/199%、“许可证事后被吊销”；改为通用表述，并加测试防止再次出现 | `prompts.py`；测试 |
| 5. fused 模板预填“没问题”的值 | 所有信号的示例值改为 `"unknown"`，并注明是占位符，不是默认值 | `prompts.py` `FUSED_USER` |
| 5. 模型自报的置信度过粗 | Judge 新增输出 `fake_probability`，校准优先使用它 | `prompts.py`；`calibration.py` |
| 6. 校准会抵消槽位保护 | `fake_score` 以最终预测为准；被槽位保护改判的样本得分为 1.0 | `calibration.py` |
| 6. 纯图像规则只在 full 下生效 | fused 的 Judge 也使用同一条纯图像规则 | `agents/judge.py` |
| 6. 缓存指纹只记录路径 | 指纹改为记录媒体文件内容的哈希（按路径、大小和修改时间记忆化）。**旧的阶段缓存全部失效** | `agents/base.py` `media_fingerprint` |
| 6. 无标点文本使数字比对失效 | 过长的无标点文本按 30 词的重叠窗口切分 | `slot_diff.py` |
| ERROR 偏多（943 条运行中约 5%） | fused 信号出现自由文本时记为 `unknown`，不再让整条样本报错 | `agents/fused_investigator.py` |
| 7. 研究方向 | 不属于代码修改，需要在实验设计中处理（同模型对照、按篡改类型分组报告、可解释性评测） | — |

## 对实验的影响

- 提示词、媒体输入和缓存指纹都变了，**之前所有 agent 结果都不能代表新模型**，需要重跑。
- 先在均衡 90 条上，用同一模型（qwen3-vl-plus）比较三组：单次调用、新 agent 不检索、新 agent 检索。确认不弱于单次调用后，再跑 943 条。

## 同模型三组对比（均衡 90 条，qwen3-vl-plus，8 帧，2026-11-16）

| 组 | Balanced Acc. | Macro-F1 | REAL 召回 | FAKE 召回 | FAKE→REAL | REAL→FAKE | ERROR | tokens |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| A 单次调用（论文提示词） | 62.2% | 57.5% | 28.9% | 95.6% | 2 | 32 | 0 | 23 万 |
| B 新 agent，不检索 | 61.1% | 61.7% | 51.1% | 71.1% | 12 | 20 | 3 | 仅 Judge 14 万（fused 复用 C 组） |
| C 新 agent，检索 | 62.2% | **63.3%** | 62.2% | 62.2% | 16 | 15 | 3 | 110 万 |
| 参考：旧 agent 不检索（11/07） | 61.1% | 61.0% | 44.4% | 77.8% | 9 | 23 | 3 | — |

- 所有两两配对的 McNemar 检验 p 均为 1.000，四组之间没有可区分的差异。
- 改动后，检索不再拉低结果：11/07 同一子集上检索使 Balanced Acc. 从 61.1% 降到 54.4%，这次检索组为 62.2%，不检索组为 61.1%。
- 新 agent 在 Balanced Acc. 上仍未超过同模型单次调用，但判断更均衡：Macro-F1 为 63.3%，单次调用为 57.5%；单次调用的 REAL 召回只有 28.9%。
- 换用更强的基础模型影响更大。同样 90 条上，qwen3.8-omni-flash 单次调用的 Balanced Acc. 为 67.8%，qwen3.5-27b 为 65.6%（取自已有的 1950 条运行，未产生新的 API 费用）。
- 检索问题：Tavily 返回 HTTP 432，共 29 次查询失败，涉及 10 条样本，可能是额度已用完；数据集原文 URL 的命中从 30 条降到 5 条，与日期上限和排除辟谣站点有关。有日期过滤后被剔除的结果为 0，另有 143 篇证据没有日期。
- 样本量只有 90 条，置信区间约为 ±10 个百分点，结论只能视为方向性参考。

## 换用 qwen3.8-omni-flash 的同模型对比（均衡 90 条，不检索，2026-11-16）

Tavily 仍返回 HTTP 432（单条查询测试也失败），所以本次只比较不检索组。音频仍以转写文本输入，与 1950 条单次调用的设置一致。

- 同模型下 agent 比单次调用高 3.3 个百分点（只有 agent 判对 12 条，只有单次调用判对 9 条，McNemar p = 0.664），**方向为正但不显著**。
- 提升全部来自 REAL 召回（80.0% → 86.7%）；FAKE 召回没有变化（55.6%），仍有 20 条假新闻被判为真，这是当前最主要的短板。
- 8 帧与 16 帧的单次调用结果相同，帧数不是瓶颈。
- 每条约 1.05 万 tokens，是单次调用的 4 倍。

### omni-flash 的输出格式问题及修复

首次运行有 6 条 ERROR（当时 Balanced Acc. 同为 67.8%）：4 次模型直接返回空的 `{}` 或 `[]`，2 次把 `relations`、`signals`、`retrieval` 错误地嵌套进下一层。修复与模型无关，不改变判决逻辑（`agents/base.py`）：

- 模型返回空内容时，原样重发一次请求；不再对空内容做“JSON 修复”。之前这种修复会生成全为 null 的判决并被缓存为成功。
- `--resume` 时不复用缓存中的空输出。
- 必需的顶层键如果被嵌套在下一层，原样移回顶层，不增删任何内容。
- 新增 3 个测试，本地测试 111/111 通过。

只重跑了这 6 条：2 条直接从缓存解析成功，4 条重新调用模型，其余 84 条未变。注意：这 6 条是在看到结果后重跑的，修复本身是通用的，但重跑引入了一次额外采样。如果按出错即判错，agent 为 67.8%，与单次调用持平。
